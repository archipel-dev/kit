# Theme generator

Generates the kit's bundled IntelliJ Community themes and editor color schemes from the
upstream **data files** (Apache-2.0, see [`NOTICE.md`](../../NOTICE.md)). Only color and
metric values are read; no source code (`.java`, `.kt`), icons or artwork.

```bash
git clone --depth 1 --branch idea/262.10968.63 https://github.com/JetBrains/intellij-community /tmp/ic
python3 -I tools/themes/generate.py --community /tmp/ic --tag idea/262.10968.63
git diff --stat   # review: the output must change only when the input or the mapping did
```

Python 3 standard library only. Run it with `-I` (the script adds its own directory to the
import path). The output is deterministic: running it twice gives byte-identical files, which
is how to check a change (`generate.py` twice, then `git diff --exit-code`). `--commit` records
the checkout's commit (default: `git rev-parse HEAD` in the checkout). The checkout can be
shallow and sparse; it needs `platform/platform-resources/src/{themes,META-INF,DefaultColorSchemesManager.xml}`,
`plugins/laf/{macos,win10}/resources` and `plugins/color-schemes/*/resources`.

## What it writes

| Output | Content |
|---|---|
| `crates/archipel-kit/src/theme/generated/ui_<id>.rs` | per UI theme: every resolved UIManager key (colors, numbers, flags, insets/sizes, sorted) and the function that fills `Colors` |
| `crates/archipel-kit/src/theme/generated/scheme_<id>.rs` | per editor scheme: its own colors and text attributes, and the function that fills `EditorColors` |
| `crates/archipel-kit/src/theme/generated/mod.rs` | registries (`Theme::all()`, `EditorScheme::all()`) and the `Theme::islands_dark()`-style constructors |
| `docs/theme-mapping.md` | the mapping, what fell back to measured values, validation and geometry tables |
| the `generated:validation` block of `docs/theming.md` | the comparison with the hand-measured `Theme::dark()` / `Theme::light()` |

Generated Rust starts with `// @generated by tools/themes — do not edit`.

## Files

| File | Role |
|---|---|
| `inputs.py` | which theme JSON and scheme XML files ship, their ids, names and constructors |
| `resolve_ui.py` | `parentTheme` chains, named colors, `*` keys → flat key tables |
| `resolve_scheme.py` | scheme XML, `parent_scheme` chains, attributes |
| `mapping.py` | **the mapping table**: kit field → IntelliJ keys, written once |
| `evaluate.py` | applies the mapping; reads the measured palettes out of `theme.rs` |
| `emit_rust.py`, `report.py` | the outputs |

## How a UI theme is resolved

IntelliJ's `*.theme.json` files are layered. For `Islands Dark` the chain is
`Darcula → ExperimentalDark → Islands Dark` (`parentTheme` ids are the `themeProvider` ids of
`PlatformExtensions.xml` and the two laf plugins' `plugin.xml`; the classic High Contrast file has
no provider at the pinned tag and is added by hand in `inputs.py`).

1. **Palette (`colors`)**: merged over the whole chain, child names win, then resolved
   (`#RGB`, `#RRGGBB`, `#RRGGBBAA` with alpha last, or the name of another entry). A child that
   redefines a palette name therefore also changes every parent entry that uses the name:
   that is how the Islands themes retint `ExperimentalDark`.
2. **`ui` keys**: nested objects become dotted keys (`"Button": {"arc": 8}` → `Button.arc`);
   OS dictionaries take `os.linux`, then `os.default`; `_comment` keys are dropped. A value is a
   color literal, a palette name, the name of another `ui` key (alias), a number, a boolean, an
   insets/size string (`"4,12,4,12"`, `"72,28"`), or something not stored: Java class names,
   icon paths and border specs (`"1,1,1,1,#5A5D63"`) are skipped, and the few values that stay
   unresolved are listed per theme in `docs/theme-mapping.md`.
3. **`*` entries** (`"*": {"background": …}`): applied layer by layer, before that layer's
   explicit keys. A star entry sets `Component.prop` for every existing key that ends in
   `.prop`, including keys an earlier layer (for example Darcula) set explicitly, then the layer's
   own keys override it. IntelliJ applies it to the UIManager defaults, which the base look and
   feel defines in Java code and which is not read here. The key set is approximated by the keys
   the layers so far set, plus Swing's standard component names for the properties the root theme
   (Darcula) declares star entries for. Keys that exist only in the Java base defaults are
   therefore missing from the tables; the mapping falls back for them (below).
4. **Base look and feel values** that exist only in Java code are not available. Where a kit
   field needs one, the field keeps the kit's **measured value** (`Theme::dark()` for dark
   themes, `Theme::light()` for light ones), and `docs/theme-mapping.md` lists the fields that
   fell back per theme.

The theme's editor scheme is its `editorScheme` (parent chain included); a theme without one
(macOS Light, Windows 10 Light, Darcula) uses `Default` (light) or `Darcula` (dark), as the IDE
does.

## How an editor scheme is resolved

A scheme file has `<colors>` (named colors; an empty value means "none" and stops inheritance)
and `<attributes>` (`TextAttributesKey` name → foreground, background, font type, effect, error
stripe color, or `baseAttributes`). `parent_scheme` chains go through `Default`, `Darcula` and
the other bundled schemes. An attribute a scheme defines replaces the parent's attribute of that
name as a whole, `baseAttributes` starts from another key, and the colorblind variants
(`deuteranopia`, `protanopia`) are ignored. Color values without `#` are hex: up to six digits
are RGB (`0` is black), eight are RRGGBBAA. `FONT_TYPE` is 0 plain, 1 bold, 2 italic, 3 bold
italic; `EFFECT_TYPE` 0 box, 1 line, 2 wave, 3 strikeout, 4 bold line, 5 bold dotted, 6 search
match, 7 rounded box (checked against the keys that use them: deprecated is 3, errors are 2).

The Rust side keeps each scheme's own colors and attributes and resolves the chain at lookup
(`EditorScheme::color`, `attributes`), so a scheme file costs only what it defines.

## The mapping table

`mapping.py` holds `COLORS` (fields of `Colors`) and `EDITOR` (fields of `EditorColors`). Each
entry is a kit field and a list of IntelliJ sources; the first that resolves wins. The
syntax is documented at the top of that file. **To map a new field**, append a line, run the
generator, and read `docs/theme-mapping.md`: it reports the fields that fell back and compares
Islands Dark and Light with the measured palettes. A field not in the table is simply kept at
the measured value, so fields other people add to `Colors` keep working. A field named in the
table that does not exist in `theme.rs` stops the generator.

## Adding a theme or scheme

Add it to `UI_THEMES` / `SCHEMES` in `inputs.py` (with its data file), run the generator,
add a test line if it needs one (`tests/themes.rs` iterates `Theme::all()` and
`EditorScheme::all()`), accept the new snapshot with `UPDATE_SNAPSHOTS=1 cargo test -p
archipel-kit --test theme_gallery`, look at it, and extend the file list in `NOTICE.md`.
